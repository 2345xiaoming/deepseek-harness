# 反思过滤器失败时 fail-open：绝不销毁 finding

评审管线的 reflection filter 判定哪些评论被证伪时，其自身失败（调用异常、无结构化输出）一律当作"零删除"处理——正确的评论绝不会因过滤基础设施故障而消失。代价是过滤器故障期间会保留本应删除的错误评论，我们认为这个方向的错误便宜（审阅者多花几秒），反方向昂贵（真 finding 静默消失、无人知晓）。

## Considered Options

- **fail-closed（失败即认为全部可疑）**：被拒。与移植源（alibaba/open-code-review 的 review_filter 设计）的结论一致——"保留错误评论的代价是审阅者几秒注意力，删除正确评论的代价是它永远不为人知"。
- **失败时降级为确定性检查**：被拒，投机复杂度；确定性定位校验已在过滤之前独立工作。
